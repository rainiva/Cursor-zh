# Cursor 抗更新翻译安全网设计

日期：2026-07-17
状态：待用户评审的草案

## 前提假设

1. 首要目标是：即使 Cursor 更新后 bundle 被重命名、拆分、采用不同的压缩方式，或改由不同组件路径渲染，也要保住已有的中文翻译。
2. 对于完全新增的 Cursor 文案，如果没有可用的翻译来源，就无法可靠地完成翻译。系统必须自动发现这些文案，但默认不得在运行时将其发送给联网翻译服务，也不得静默使用机器翻译。
3. `performance` 继续作为默认模式。安全网必须采用事件驱动、界面域限定和有界执行方式，不得引入全局轮询或定时全页面补扫。
4. 继续支持现有的 `apply`、`ensure`、`verify`、`start`、`uninstall`、备份及干净状态恢复语义。
5. 当前工作区中尚未提交的改动属于用户。本设计不授权重写或丢弃这些改动。

如果假设 1 或假设 2 不成立，特别是如果要求自动联网翻译从未见过的文案，则必须先明确隐私、服务提供方、缓存和质量策略，再进入实施。

## 目标

构建一套确定性的、能够适应软件更新的翻译安全网，使其能够：

- 让稳定翻译走成本最低、可靠性最高的路径；
- 在 bundle 结构和压缩器输出发生漂移后重新定位已知翻译，同时不再不断积累版本专用的源码片段；
- 为每个关键界面域提供显式且有界的兜底路径；
- 在未见过或存在歧义的文本被错误报告为“已覆盖”之前将其识别出来；
- 在修改已安装的 Cursor 文件之前，先完成构建暂存和验证；
- 保持启动和交互性能。

当 Cursor 更新从一次新的截图排查或手工搜索替换工作，转变为一次兼容性分类过程时，这套机制才算成功。

## 当前证据

2026-07-17 针对 Cursor `3.12.10` 和 VS Code 内核 `1.128.0` 的真实验证结果如下：

- 合并后映射：`1756`；
- 运行时映射：`615`；
- 运行时头部：`101.9 KB`；
- 运行时治理阶段：`phase2`；
- `verify` 总耗时：`9.92 s`；
- 覆盖率分析耗时：`9.44 s`，占 `verify` 的 `95.2%`；
- Cursor Win 目标：`1307` 个，其中 `2` 个未覆盖（`Agent ID`、`Agent URL`）；
- desktop 和 Glass bundle 都没有通过 Marketplace 容错 hook 检查；
- 两个已安装的翻译 bundle 都仍然包含扩展缓存提示逻辑，需要重新执行 `apply`。

当前映射清单还显示：

- Cursor Win 常用条目 `1338` 个；
- 动态条目 `197` 个；
- 锚点条目 `64` 个，全部绑定到显式锚点 ID；
- 已安装产物中注入了 `615` 条运行时规则；
- 仅 Product Tips hook 合约就包含 `12` 个压缩源码变体。

结论：Phase 2 已经控制住了运行时体积。剩余的脆弱性主要来自对源码形态的耦合、锚点覆盖面过窄、更新后发现问题过晚，以及部分合约缺少明确的兜底归属。

## 设计原则

### 稳定身份优先于源文本

每个重要翻译单元都必须拥有稳定的 `translationId`。英文源文本只是别名，不再充当身份标识。系统可以通过命令 ID、设置键、NLS 键、JSON 字段、bundle 语义特征或界面域限定的渲染文本来定位翻译单元。

### 确定性优先于模糊匹配

只有在定位结果唯一且后置条件全部通过时，系统才允许自动应用翻译。相似度可以用于排列待处理候选项，但绝不能仅凭模糊相似度修改源码或可见界面。

### 兜底必须有明确归属且边界有限

每个阻断级合约都必须声明主路径和兜底路径。没有有效兜底的合约一旦失败，就必须阻止提交预构建产物。运行时兜底必须指定所属界面域根节点和激活事件。

### 先预构建，再提交

更新后的重建过程采用两阶段事务：先在工作区状态目录中预构建并验证，再提交完整受管目标集合。该集合包括安装产物、`argv.json`、locale mirror、扩展 NLS、语言包缓存、启动器和快捷方式。预构建失败或被阻断时，所有受管目标均保持不变；准入前只允许写入 `state/generated/<build-id>` 产物和诊断。

### 未知内容必须可见，不能靠猜测处理

未见过的文本必须连同上下文和优先级记录到本地更新报告中。它不能被计入已覆盖内容，也不能由未经批准的联网服务静默翻译。

## 架构

### 第 0 层：官方语言目录归属

只要存在稳定的模块/键组合，就优先使用官方简体中文语言包和扩展 NLS 目录。

职责：

- 解析 NLS 模块别名；
- 写入前验证键对齐情况和消息数量；
- 目录翻译优先于源码替换；
- 在构建清单中按 `translationId` 记录目录归属。

失败行为：

- 在提交前完成目录不匹配分类；
- 关键翻译单元只有在显式声明了下层路径时，才允许继续向下兜底。

### 第 1 层：索引化静态字面量归属

使用 workbench 索引，在构建时翻译稳定的引号字面量。这仍是直接存在于 bundle 中的文本的默认处理方式。

职责：

- 使用绑定到稳定 `translationId` 的精确别名或规范化别名；
- 要求目标唯一，或显式声明允许匹配多个目标及其基数；
- 将匹配数量和源 bundle ID 写入构建清单；
- 转换后验证目标中文文本确实存在。

此层没有运行时成本。

### 第 2 层：语义定位归属

使用语义定位器替代不断增长的压缩源码片段列表。定位器由多项稳定证据共同组成，例如：

- 命令、操作、设置、菜单或遥测 ID；
- 稳定属性名和邻近字符串常量；
- `title`、`label`、`placeholder` 或 `description` 等字段路径；
- 忽略压缩变量名称的相对 token 或数据流形态；
- 预期所属的 bundle 能力；
- 预期匹配基数；
- 证明 hook 或翻译调用只被插入一次的后置条件。

定位器求值会产生四种状态之一：

- `resolved`：恰好找到一个有效目标，且所有后置条件均通过；
- `relocated`：旧指纹已经变化，但找到了唯一的语义目标；
- `fallback`：不存在可安全修改的源码目标，但合约拥有有效的运行时兜底；
- `blocked`：目标存在歧义、缺失或后置条件失败，并且没有有效兜底。

版本专用变体只能作为带有到期原因的临时兼容性夹具存在，不能再作为默认扩展机制。

### 第 3 层：界面域限定的运行时安全网

无法通过第 0—2 层安全应用的已知翻译，以小型界面域分片的形式提供。

激活规则：

- 仅在已注册界面域根节点挂载、获得焦点或打开时激活；
- 只观察该界面域子树；
- 使用有界空闲批次翻译新增节点；
- 界面域卸载时断开观察器；
- 只加载该界面域对应的分片；
- 不得轮询或安排全页面补扫。性能模式可以在 `document.body || document.documentElement` 上保留恰好一个全局发现观察器，但仅使用 `childList + subtree`；它只把新增根节点入队，每个 idle 批次最多按已登记界面域选择器检查 `30` 个节点，绝不执行翻译、文本遍历、属性处理或分片解析。

匹配规则：

- 精确别名；
- 规范化精确别名；
- 保留占位符的、已批准的参数化模板；
- 具有明确字段或界面域归属的作用域正则表达式。

继续禁止全局短词匹配和无作用域的模糊匹配。

### 第 4 层：更新发现与隔离

提交前，将新安装配置与上一个兼容配置进行比较。

更新配置只包含允许再分发的元数据：

- Cursor 和 VS Code 版本；
- 源文件哈希和 bundle 能力 ID；
- NLS 模块/键清单哈希；
- 语义定位器结果；
- 合约结果；
- 按界面域统计的已知别名命中、别名变化、静态未知源码字符串，以及隐私安全的运行时未知指纹/计数；
- 运行时分片大小和预算。

未知或存在歧义的字符串会写入本地隔离报告。默认处理队列如下：

1. 没有兜底的阻断级合约；
2. 具有唯一语义身份候选项的已变化别名；
3. 关键界面域中的新增字符串；
4. 非关键可见区域中的新增字符串；
5. 后台清单噪声。

隔离报告只能保存在本地，并且必须区分来源。静态 harvest 可以保留从 Cursor bundle 提取的原始字面量。运行时只有节点命中界面域显式 `quarantineSelectors` UI chrome 白名单时才允许保留原文；即使位于允许的界面域内，`input`、`textarea`、`[contenteditable]`、编辑器、终端、聊天/消息正文、代码块和已声明动态值区域也必须拒绝采集。其他运行时未知内容只能保存界面域、出现次数，以及使用永不持久化且不写入报告的临时会话密钥生成的 HMAC-SHA-256 指纹。如果无法安全生成指纹，只记录聚合计数，绝不能退回保存原文。

相似度只能用于提出待评审别名。要将其提升为正式映射，必须显式更新映射并补充测试。

## 翻译单元合约

概念模型如下：

```js
{
  translationId: 'composer.send_follow_up',
  changeText: '继续追问',
  aliases: ['Send follow-up', 'Add a follow-up'],
  owner: 'composer',
  primary: {
    kind: 'semantic',
    locatorId: 'composer.follow_up_action',
    cardinality: 1
  },
  fallback: {
    kind: 'runtime-surface',
    surface: 'composer',
    match: 'normalizedExact'
  },
  severity: 'error',
  placeholders: []
}
```

必须满足以下不变量：

- `translationId` 稳定且唯一；
- 同一作用域内，每个别名只能解析到一个有效中文翻译；
- 阻断级翻译单元必须拥有已证明的主路径或当前版本兜底证明；
- 占位符和快捷键助记符必须保留；
- 运行时归属必须对应已注册界面域；
- 旧别名必须继续用于更新兼容，直到收紧规则明确将其移除。

“当前版本兜底证明”不是历史布尔值。它必须包含兜底测试 ID 及本次通过结果、分片编译成功、作用域/生命周期/占位符/隐私合约结果、唯一命中的当前 Cursor 能力证据签名，以及由当前 bundle 哈希、NLS 清单哈希、运行时治理快照和工具版本共同生成的证明键。任一部分缺失、歧义、失败或过期，证明立即失效并阻断准入。真实 UI 操作仍是发布验收门禁，不要求每位用户每次运行 `ensure` 时交互验证。

## 更新准入状态机

`ensure` 必须在写入前对安装状态进行分类：

```text
UNCHANGED -> 复用已验证产物
KNOWN_DRIFT -> 根据当前源码重建、验证并提交
DEGRADED -> 仅当所有失败主路径都有当前版本兜底证明时才提交
BLOCKED -> 保持所有受管目标不变，并输出具体阻断合约
```

预构建阶段：

1. 检测安装目录和语言包兼容性；
2. 清点所有候选 bundle 和 NLS 目录；
3. 构建索引和语义能力配置；
4. 解析每个翻译单元的处理路径；
5. 在 `state/generated/<build-id>/` 下生成翻译产物；
6. 执行静态、运行时分片、生命周期和干净状态的提交前验证。

提交阶段：

1. 确认 Cursor 和安装范围内的更新进程已停止；
2. 原子获取由 `apply`、`ensure`、`uninstall` 共享的按安装实例 cursor-zh 事务锁；
3. 重新计算每个受管目标的存在性/内容快照，并要求与预构建快照完全一致；
4. 创建或验证回滚快照；
5. 通过统一事务登记表写入预构建的安装产物和外部产物；
6. 验证所有受管目标的哈希/存在状态和合约后置条件；
7. 持久化已接受的兼容性配置；
8. 如果提交验证失败，则按提交逆序恢复每个已提交受管目标，并保留预构建诊断信息；
9. 只有提交后验证成功或完整回滚结束后才释放事务锁。

进程占用、有效锁或并发快照漂移必须在任何受管写入前生成带明确 `busy`、`transaction-active` 或 `concurrent-drift` 证据的 `BLOCKED`；工作区预构建产物和诊断保留供重试。锁文件必须原子创建，并记录 PID、进程启动时间、所有者令牌、安装标识和构建/操作 ID。陈旧锁只有在超过最小陈旧时间，并且 PID 不存在或启动时间不匹配时才能回收；仅凭文件年龄永远不够。

## 状态 schema 与跨版本恢复

每个新 manifest 都声明 `schemaVersion` 和 `minReaderVersion`。当前工具为无版本旧格式 `v0` 和最近两个正式 schema 提供只读适配器。适配只在内存中迁移；旧 manifest 和备份目录永不改写、重命名或删除。只有预构建提交及提交后验证成功，才发布新的已接受 manifest。

prepare 还会生成候选稳定 `recovery-capsule.json`，只包含恢复必需数据：胶囊 schema/最低读取版本、工具/操作/构建标识、已验证备份指针、规范化受管目标列表，以及每个目标提交前的存在性/哈希/恢复来源。候选胶囊属于工作区状态，失败后可以保留；只有成功提交后，已接受 manifest 才引用它。遇到未知未来 manifest schema 时，`apply` 和 `ensure` 必须阻断。`uninstall` 只有在受支持恢复胶囊能够独立验证其 schema、安装标识、备份内容、受管目标和原状态证据时，才允许跨越该边界；否则阻断并要求使用匹配或更高版本工具。恢复过程禁止猜测。

## 性能预算

在与基线相同的机器和用户配置上，本设计必须满足以下全部条件：

- `performance` 模式下不存在定时轮询或计划式全页面补扫；
- 全局发现观察器恰好一个，仅使用 `childList + subtree`，不执行翻译，每个 idle 批次最多检查 `30` 个新增根节点；
- 启动核心运行时载荷 `<= 80 KB`；
- 每个延迟加载的界面域分片在未压缩状态下 `<= 20 KB`；
- 每个已挂载的注册界面域最多只有一个活动观察器；
- 每个运行时批次最多处理 `30` 个文本节点，然后主动让出执行权；
- 热路径且内容未变化的 `ensure` `<= 2 s`；
- 热路径 `verify` `<= 3 s`；
- 冷路径 `verify` `<= 8 s`；
- 更新预构建和验证 `<= 30 s`，不包括备份复制时间；
- 运行时不得通过网络请求翻译文本；
- 启动时不得解析尚未挂载界面域的映射。

如果超过预算，`verify` 必须报告具体责任界面域或阶段，而不是只给出全局总数。

测量协议属于门禁本身。载荷限制（core `80 KB`、单分片 `20 KB`）在所有环境都必须硬阻断。墙钟证明仅在登记过的专用基线机器/配置上有效：热验证先预热 1 次，再测量 5 次，最慢一次必须 `<= 3 s`；冷验证每轮只清除 cursor-zh 会话缓存而不清除操作系统文件缓存，共测量 3 次，最慢一次必须 `<= 8 s`。通用 CI 和开发机运行确定性阶段预算测试，墙钟结果标记为 `UNQUALIFIED`，不能作为发布证明。必需的自托管基线任务缺失、计算出的机器/配置指纹与登记值不符，或任一测量超限，都必须阻止发布。

## 可靠性与安全边界

始终执行：

- 所有生产行为变更遵循 RED -> GREEN -> REFACTOR；
- 编辑前使用当前文件系统和 Git 证据确认状态；
- 对编码敏感文件使用补丁式编辑和显式 UTF-8 读取；
- 保持 `main.js` 字节级不变这一安全要求，以及用户配置目录行为；
- 写入任何受管目标前暂存更新产物；
- 卸载时必须先完成验证，再清理状态；
- 分别报告 `resolved`、`fallback`、`unknown` 和 `blocked`。

必须先询问：

- 增加解析器或其他生产依赖；
- 启用任何联网翻译服务；
- 在本地工作区状态以外存储已渲染界面文本；
- 将阻断级合约降级为警告；
- 扩大运行时观察器作用域。

绝不执行：

- 仅凭模糊匹配修改源码；
- 在多个源码目标之间静默猜测；
- 添加全局短词映射；
- 将未知文本计为已翻译；
- 添加全页面轮询救援路径；
- 当阻断级合约既没有已解析的主路径，也没有当前版本兜底证明时提交预构建更新；
- 分发 Cursor bundle、用户数据、备份或采集到的专有源码。

## 项目结构

建议按以下职责划分；本规格获批后，再由实施计划确定准确的文件拆分：

```text
translations/meta/
  translation-units.json       稳定 ID、归属、路径和兜底策略
  surfaces.json                界面域根节点、激活方式和预算元数据
  runtime-governance.json      全局和各界面域的收紧预算

scripts/lib/compatibility/
  update-profile.js            可再分发的更新能力配置
  admission.js                 unchanged/known-drift/degraded/blocked 决策
  semantic-locator.js          唯一结构目标解析
  locator-postconditions.js    补丁/hook 证明检查

scripts/lib/mapping/
  translation-units.js         结构校验和别名索引
```

## 代码风格

优先采用结果明确的纯分类函数：

```js
function classifyLocatorOutcome({ matches, postconditions, fallbackAvailable }) {
  if (matches.length === 1 && postconditions.every(Boolean)) {
    return { status: 'resolved', target: matches[0] };
  }
  if (fallbackAvailable) {
    return { status: 'fallback', reason: matches.length > 1 ? 'ambiguous' : 'missing' };
  }
  return { status: 'blocked', reason: matches.length > 1 ? 'ambiguous' : 'missing' };
}
```

不得用布尔值掩盖歧义。结果必须携带足够证据，供 `verify` 和更新报告使用。

## 测试策略

### 合约与模式测试

- 拒绝重复的 `translationId`；
- 拒绝在同一作用域内解析到冲突译文的别名；
- 拒绝既没有主路径也没有兜底的阻断级翻译单元；
- 拒绝没有注册界面域的运行时兜底；
- 验证占位符和快捷键助记符得到保留。

### 语义定位器变形测试

每个定位器夹具都必须能够适应：

- 压缩变量重命名；
- 引号和空白变化；
- 不影响行为的函数重排；
- bundle 文件名变化；
- bundle 在 desktop、Glass 和辅助 chunk 之间拆分；
- 插入无关的邻近字面量。

遇到以下情况时，它必须进入 `blocked` 或 `fallback`，绝不能修改错误位置：

- 出现两个看似有效的目标；
- 稳定的命令、设置或操作 ID 消失；
- 无法证明后置条件。

### 运行时安全网测试

- 界面域激活前不加载其分片；
- 只翻译已注册根节点内部的节点；
- 卸载时断开观察器；
- 批次处理 `30` 个节点后主动让出执行权；
- 唯一全局发现观察器只监听 `childList + subtree`，每个 idle 批次最多检查 `30` 个新增根节点，不执行翻译且绝不查询整个 document；
- 动态占位符在翻译后保持不变；
- 静态未知源码字面量可以保留原文；运行时 UI chrome 只有符合显式选择器策略时才能保留原文；
- 运行时用户内容和动态值区域绝不进入报告，其他运行时未知内容只携带会话级 HMAC 指纹、界面域和出现次数；
- 不安装轮询定时器或计划式全页面补扫。

### 更新事务测试

- 更新配置未变化时复用已验证产物；
- 已知漂移基于当前原始文件重建；
- 降级模式只有在当前版本兜底证明完整、唯一且有效时才能提交，过期证明键必须阻断；
- 被阻断的预构建对工作区状态之外的所有受管目标执行零写入；
- Cursor/更新进程活动、有效事务锁或 prepare 到 commit 之间的任何受管目标漂移，都必须在备份和受管写入前阻断；
- 陈旧锁回收必须同时满足陈旧时间与 PID/启动时间不匹配；并发 `apply`/`ensure`/`uninstall` 共享同一个按安装实例锁；
- 提交后验证失败时恢复每个已提交受管目标原先的存在性和内容状态；
- 卸载仍能恢复英文，并在清理状态前完成验证。

### 状态迁移与恢复测试

- 无版本 `v0` 和最近两个正式 schema 在内存中适配，源文件保持不变；
- 成功提交发布引用已验证恢复胶囊的新 schema manifest，失败/阻断预构建仍以旧 manifest 为权威；
- 旧备份字节和路径保持不变；
- 未知未来 schema 阻断 `apply`/`ensure`；
- 未知未来 schema 只有通过兼容且完整验证的胶囊才能执行 `uninstall`；
- manifest 损坏、胶囊损坏、安装标识错误或备份指针无效时安全失败，并给出可操作版本提示。

### 性能测试

- 核心载荷和每个分片都符合大小预算；
- 所有环境都对载荷大小回归执行硬阻断；
- 登记基线执行 1 次预热、5 次热测量和 3 次仅清 cursor-zh 缓存的冷测量，并以最慢样本执行门禁；
- 未登记环境报告 `UNQUALIFIED`，不能满足发布性能门禁；
- 自托管基线证据缺失或指纹不匹配时阻止发布；
- 界面域激活工作量受节点数限制，并能主动让出执行权；
- 未挂载界面域不会增加观察器或映射解析成本。

### 发布与 readiness 测试

- shadow 完整执行新引擎证据流程，但新引擎受管写入为零；
- 即使存在参数，canary 也拒绝未登记或不可抛弃的安装；
- 被接受的 canary/enforced 提交记录 `lastKnownGood` 和唯一待激活 nonce；
- bootstrap readiness 必须同时满足 workbench 完成加载和有界非空 DOM 探针，并且只确认匹配 nonce；
- readiness 缺失绝不终止 Cursor；下一次已停止的 `start`/`ensure` 在事务锁内恢复 `lastKnownGood`；
- `BLOCKED` 绝不自动选择旧路径，过期的仅维护旧路径参数必须失败；
- enforced 提升需要全部门禁，以及覆盖两个构建且包含一个真实上游更新的证据。

### 真实操作验收

对于一个受支持的真实 Cursor 版本，至少验证：

- 启动能够正常进入工作区，没有白屏或用户配置目录漂移；
- Composer 追问操作显示中文；
- 模型选择器搜索显示中文；
- 设置搜索显示中文；
- 至少一个对话框界面域通过声明的兜底路径完成翻译；
- Marketplace 能够打开，且不需要全局运行时扫描；
- 卸载后，同一安装能够恢复到通过验证的英文状态。

## 成功标准

### 更新韧性

- 所有阻断级翻译单元都拥有稳定 ID、明确归属和已声明的兜底策略；
- 合成漂移矩阵能够保留 `100%` 的已知阻断级翻译，且不增加版本专用的压缩源码片段；
- 存在歧义的语义匹配只能产生 `fallback` 或 `blocked`，绝不能触发源码修改；
- 不受支持的 Cursor 更新在预构建成功前不得修改当前安装；
- commit 使用按安装实例排他锁和预构建快照精确复核，防止并发或过期状态安装；
- 从未见过的静态文本和隐私安全的运行时证据会进入更新隔离报告，且不会被报告为已覆盖；
- 运行时隔离报告不得包含用户输入、编辑器/终端/聊天/代码内容，也不得包含显式 UI chrome 白名单之外的原文。

### 翻译覆盖

- 阻断级合约：`100%` 已解析，或由当前版本兜底证明覆盖；
- 警告级合约：`>= 95%` 已解析或由兜底覆盖，其余内容必须明确列出；
- 在夹具中移动或改名的已知别名：`100%` 保留；
- 恒等映射或缺失规则不得计为有效覆盖。

### 性能

- “性能预算”一节中的全部预算通过；
- 发布证据来自登记基线指纹和完整测量样本集，绝不使用通用 CI 墙钟结果替代；
- 不得退化为轮询、全局补扫或预先解析全部界面域映射；
- 运行时工作量随已挂载界面域中的变化节点数量增长，而不是随页面总大小或映射总数增长。

### 生命周期安全

- 完整 Node 测试套件通过；
- `apply`、`verify`、`ensure`、`start`、`uninstall` 和 `verify-clean` 集成路径通过；
- 旧状态夹具和兼容恢复胶囊在不修改旧 manifest/备份的前提下通过；未来或损坏的不受支持状态安全失败；
- shadow/canary/enforced 转换、readiness 确认、下次启动恢复、发布证据和旧写入器到期门禁全部通过；
- 真实启动和卸载操作路径通过；
- 不出现用户配置目录漂移、白屏或回滚退化。

## 迁移策略

### 发布模式与最后已知良好状态恢复

引擎有三种显式发布模式，并记录在 manifest/证据中：

1. `shadow`：完整执行 prepare、准入、证明和对比，但新引擎不得写受管目标；过渡版本仍由旧写入器实际写入。
2. `canary`：只有显式登记的可抛弃安装，并显式选择 `--safety-net-canary` 时，才允许新事务写入。
3. `enforced`：只有确定性、隐私、恢复、真实操作和合格基线性能门禁全部通过，且证据覆盖至少两个不同 Cursor 构建（其中一个必须是真实上游更新）后，新事务才成为默认路径。

每次被接受的 canary/enforced 提交都记录 `lastKnownGood` manifest、快照和已验证恢复胶囊，然后创建一次性待激活 nonce。生成的 bootstrap 只有在 workbench 窗口完成加载且有界 DOM readiness 探针成功后才报告就绪。提交或提交后验证失败立即回滚。如果 readiness 一直未确认，工具绝不终止正在运行的 Cursor；下一次 `start` 或 `ensure` 在 Cursor 已停止并持有同一安装实例锁时，先自动恢复 `lastKnownGood`，再启动。

`BLOCKED` 绝不自动退回旧写入器。旧写入器只在一个过渡版本中以显式维护参数和警告保留，并声明到期版本；enforced 证据通过后删除。发布提升在以下任一情况失败：证据缺失、未覆盖一个真实上游更新/两个不同构建、存在失败门禁，或仍依赖已过期旧写入器。

1. 引入稳定翻译单元模式和兼容性报告，但不改变运行时行为。
2. 添加语义定位器引擎，并以一个脆弱 hook 作为纵向切片进行迁移。
3. 添加预构建准入，并证明阻断情况下完整受管目标集合零写入。
4. 添加按界面域拆分的运行时分片，并迁移现有由兜底负责的合约。
5. 按界面域分批迁移常用映射和锚点。
6. 只有在等价漂移测试和真实验证都通过后，才移除被替代的压缩源码变体。
7. 逐步收紧载荷、验证耗时和旧变体预算。
8. 一个过渡版本运行 `shadow`，随后仅在登记的可抛弃安装运行 `canary`；只有完整证据允许提升到 `enforced`，提升后删除仅供维护的旧写入器。

每一步都必须能够独立发布和回滚。禁止一次性迁移全部映射。

## 已批准默认策略

1. 新出现的 Cursor 专属文案保留英文并进入本地隐私安全隔离；`ensure` 不调用联网翻译提供方。
2. 只有每个阻断级主路径失败都拥有完整的当前版本兜底证明时，`DEGRADED` 才自动启动。
3. core `80 KB`、每个分片 `20 KB`、热验证 `3 s`、冷验证 `8 s` 是基线机器/配置上的硬门禁。
